关键结论

Running=64 只表示 64 个坑被占满，不表示 64 条每步都在算。

Scheduler 每步在 token 预算（16384）内选 batch；大 prefill 可能独占一步。

调参目标：让 decode 几乎每步都能混进 batch，避免「0 generation」的长步。
